EdgeSLM_Android コンポーネント構成図

Qwen2.5-0.5B（24 層）を Snapdragon 888（HTP v68）の NPU だけで動かすための構成。PC で「書き出す → 書き換える → 量子化する → QAIRT で変換する」流れと、端末で「job を受けて ONNX Runtime ＋ QNN EP で HTP に流す」アプリ、その間の受け渡しを 1 枚にした。各部品の右上の番号は、対応する StudyMemo の章。各部品の下の ▸ の行は、その部品を作っているソースと、そのファイルが何をするか。

自作（このプロジェクトのソース） 既存のフレームワーク（PyTorch・transformers・ONNX・ONNX Runtime） Qualcomm の SDK・ハード（QAIRT・QNN・FastRPC・HTP） 調べる・測る道具（本番の流れには入らない） 受け渡すファイル
PC（Windows）— 変換パイプラインapp/pipeline/・scripts/。venv: Python 3.12 ＋ onnx・onnxruntime 1.30・torch／QAIRT 用 Python 3.10／Git Bash

このプロジェクトから派生したもの（箱だけ）

EdgeSLM ／ EdgeSLM-cpp

前段。PC での推論基盤（Python）と、その C++ 移植。基本設計③が端末へ移す予定だった生成パイプラインの元。

EdgeSLM_AndroidDemo

端末だけで会話するデモアプリ。job.cpp に generate・generate_kv、Kotlin のトークナイザ、KvCarry（会話をまたぐ KV）、画面を足した。以後のアプリ（下の 4 つ）の複製元。

EdgeSLM_AndroidScale

モデルを大きくする（1.5B・Qwen3・W4）。メモリの上限（約 1,710MiB）・位置0・K の中心化。量子化の道具は写しで受け継ぐ。Android のソースは持たず、端末側は EdgeSLM_AndroidDemo のアプリに拡張を足して使う（★2026-10-23 訂正: 旧「android アプリも写しで受け継ぐ」。Scale に Android のソースは無い）。

EdgeSLM_AndroidHead ／ Gemma4Head

LLM の h に分類ヘッドを付けて端末で判定（ルーター）。学習・評価は EdgeSLM_MultiHead_Multi。

EdgeSLM_AndroidGemma4 ／ VLM ／ VLMSpec

Gemma 4 E2B を 35 層のかたまりに分けて載せる・画像を入れる・投機的デコード。QAT の丸め（SRQ）の再現が加わる。C-14 は VLM で見つかった制約（★2026-10-23 訂正: 旧「C-14 が加わる」を 3 つまとめて書いていた）。

共通の写し

app/pipeline の量子化の道具（preprocess・quantize_qdq・p2b_ops・fix_norm_gamma・downgrade_actact_rhs・verify_artifacts・wrap_epctx など）と、アプリの C++（session・memprobe・progress・edgeslm_jni）は Android のアプリを持つ派生に写して使っている（Scale は持たない）。各派生の写しの中身は、それぞれの DoC/コンポーネント構成図.html。
