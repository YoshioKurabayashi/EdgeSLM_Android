# P12f — 自由生成が分岐する瞬間を teacher forcing で解剖する

2026-09-15 / Qwen3-0.6B 28層 KV256 / Host CPU（ONNX Runtime）/ P12e のモデルを使用

## 結論

**P12e の focused_split が「音楽をかけて」で崩れた原因は clip ではない。**
168本すべて、2つの分岐点の prefix 全位置で clip 0。陽性対照（先頭の巨大値に後続用範囲を当てる）では
168本すべて検出できたので、見逃しではない。

一方、壊れる瞬間（点B）には次の形が見えた。

- **FP32 は同じ履歴でも「音」を強く選ぶ**（18.76、2位と 4.62 差）。1ターン目の回答内容のせいではない
- **focused_split は「エ」16.11 / 「音」15.73 に逆転**（KL 1.33）
- ところが **168本の活性誤差は、focused の方が baseline より小さい**（残差 add 中央値 33.1%→30.7%）
- **両モデルとも FP32 から約30%ずれた状態**で走っており、baseline が「音」を保てたのは差の向きの違いにすぎない可能性がある

つまり、全体の誤差の大きさでも clip でも説明できず、**ずれの向き**が効いている。

## 1. 方法

- 実行方式は P12e（`temporal_qdq_experiment.Runner`）と同一。各モデルは**自前の KV** を積む
- 分岐点の直前まで、FP32 / baseline / focused_split に**同じトークン列**を食べさせる
- 範囲を変えた168本の量子化入力（`focused_build_audit.json` の `sources`）を全位置で出力させ、
  **そのモデル自身の表現範囲**からはみ出した要素を数えた
  - baseline は既存 QDQ の scale/zero point から範囲を復元
  - focused_split は位置0が shared 範囲、以降が later 範囲
  - FP32 の値にも focused の範囲を当て、「本来の分布なら clip するか」を見た
- 観測用モデルは出力を足した複製（元モデルは不変）。FP32 の外部データはハードリンクで共有

| 点 | prefix | 意味 |
|---|---:|---|
| A 最初の分岐 | 49 | 1ターン目の回答9トークン目（baseline と focused が別の語を選ぶ直前） |
| B 壊れる瞬間 | 80 | focused 自身の1ターン目回答を履歴にし「音楽をかけて」を入れた直後 |

## 2. 点A：最初の分岐は、両モデルとも FP32 から外れた接戦

| モデル | 1位 | FP32 1位の順位 | KL | logits 相対L2 |
|---|---|---:|---:|---:|
| FP32 | 「設定」16.59（2位「します」14.82） | 1 | 0 | 0 |
| baseline | 「調」14.50 | 2 | 1.328 | 24.34% |
| focused_split | 「すると」15.11 | 2 | 0.865 | 17.72% |

baseline も FP32 と違う語を選んでおり、**点A は focused だけが壊れた地点ではない**。
「調節しました」「すると、…」はどちらも文として成立する。focused の方が KL・誤差とも小さい。

## 3. 点B：壊れる瞬間

| モデル | 上位 | FP32 1位の順位 | KL | logits 相対L2 |
|---|---|---:|---:|---:|
| FP32 | **「音」18.76** / 車 14.14 / エ 13.68 | 1 | 0 | 0 |
| baseline | **「音」18.23** / エ 14.88 / え 14.31 | 1 | 0.125 | 32.48% |
| focused_split | **「エ」16.11** / 音 15.73 / え 14.92 | 2 | 1.326 | 29.34% |

- **対照**: FP32 は focused の履歴を与えても「音楽」に答える → 履歴は原因ではない
- focused は FP32 比で「エ」+2.4、「音」−3.0 動いた。FP32 で 4.6 差の非接戦が逆転している
- **logits の相対L2 は focused の方が小さい**のに、KL は10倍。**L2 は分岐を予測しない**

## 4. clip

| 範囲の当て方 | 点A prefix で clip したテンソル | 点B prefix |
|---|---:|---:|
| FP32 の値 × focused の範囲 | 0 / 168 | 0 / 168 |
| baseline × 既存範囲 | 0 / 168 | 0 / 168 |
| focused_split × 自身の範囲 | 0 / 168 | 0 / 168 |

陽性対照: 先頭トークンの FP32 値に後続用範囲を当てると **168 / 168** で clip を検出。
位置1で範囲に最も迫ったのは `node_pow_32_max` 等で使用率 0.667（＝1.5倍の余裕の上限そのもの）。

## 5. 168本の活性誤差（FP32 比・最終位置）

| 種類 | 本数 | 点A baseline→focused | 点B baseline→focused | 点B で focused が悪い本数 |
|---|---:|---:|---:|---:|
| 残差 `add_N` | 40 | 24.3% → 15.9% | 33.1% → 30.7% | 5 / 40 |
| `node_pow_N_abs` | 42 | 23.1% → 15.3% | 30.3% → 28.0% | 6 / 42 |
| `node_pow_N_max` / `maxr` | 42+42 | 15.0% → 13.5% | 12.6% → 12.6% | 28 / 42 |
| `linear_N` | 1 | 25.0% → 15.9% | 64.7% → 55.8% | 0 / 1 |

点B の残差を深さ順に見ると、浅〜中層は focused が小さく、**深い層（add_150 以降）だけ focused が1〜4ポイント悪い**
（例: add_161 35→38%、add_188 32→36%）。

## 6. 読み方と、否定されたもの

| 候補（ChatGPT 指摘の3つ） | 判定 |
|---|---|
| ① 実運用分布で clip | **棄却**（0 / 168、陽性対照あり） |
| ② clip は無いが scale/zero point の変更で重要な値の誤差が増えた | 168本の平均では**逆に減っている**。深い層の一部だけ悪化。未確定 |
| ③ 複数テンソル同時変更の相互作用 | 未検証 |

加えて重要な事実: **Host QDQ baseline 自身が、80トークン時点で残差を FP32 から約33%ずらしている。**
baseline が正しく答えるのは、ずれの向きが結果的に害にならなかったからで、
Host QDQ の精度に余裕があるわけではない。この状態では、平均誤差を少し減らす変更でも、
向き次第で答えがひっくり返りうる。

## 7. 次の切り分け候補

1. **キャッシュと最終ステップの入れ替え**: 点B で「focused が積んだ KV × baseline の1ステップ」と
   「baseline の KV × focused の1ステップ」を比べ、逆転が**積んだ KV** 由来か**最後の計算**由来かを分ける
2. 深い層（add_150 以降）だけを baseline の範囲に戻した focused で、点B の逆転が消えるか
3. 評価指標は L2 ではなく **KL と FP32 1位の順位・マージン**を主にする
