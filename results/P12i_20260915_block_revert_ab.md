# P12i — 範囲変更を1ブロックずつ戻す A/B：局所パッチは見つからず、効果は強く非加法的

2026-09-16 / Qwen3-0.6B 28層 KV256 / Host CPU / P12e の focused（先頭 shared・後続 later）から出発

## 結論

1. **1ブロックだけ戻して、全評価点を baseline 以上にする変種は無かった。** どのブロックも、ある評価点を良くすると別の点を悪くする。
2. **効果は強く非加法的。** 点B（「音」）で、7ブロックそれぞれを戻した効果の合計から予測すると +0.93 だが、全部戻した実測は +3.35。
   BANANA は予測 +0.43 に対し実測 +1.98。**ブロック間の相互作用が主**で、1ブロックずつの A/B では原因を局所化できない。
3. **P12g で「効いている KV は層14-20」だったが、層14-27 の4ブロックはどれを戻しても点B はほぼ動かない**（−0.74〜−0.41）。
   点B を動かしたのはすべて層0-13 のブロック。**状態が壊れる場所と、原因の変更がある場所は別**だった。
4. 点B を最も戻したのは「その他」2本 = **層2 の MLP（`mul_41` = SiLU(gate)×up、`linear_20` = down_proj 出力）**。
   `linear_20` は先頭トークンで 8141 に達し、**残差の巨大値（channel 35）を作り出している場所**そのもの。
   ただしこれを戻すと日本語・英語対話の1位保持が下がり、BANANA がほぼ 0 になる。
5. **集計の差はほとんどが評価点1〜3個分。** 回答位置は52点しかなく、1点の違いが 1.9%。
   baseline 85.7% と focused 87.5% の差は1点。**このデータ量では変種間の優劣をほとんど言えない。**

## 1. 方法

- 変更の単位: 層群 {0-13, 14-20, 21-27} × 種別 {残差 add, RMSNorm 補助 `node_pow_*`, その他}。空でない7ブロック
  （L0-13: その他2 / 残差23 / RMSNorm補助66、L14-20: 残差14 / 補助42、L21-27: 残差3 / 補助18）
- 層の割り当て: 層L の input_layernorm に入る残差 Add より後ろで作られたテンソルを層L とする（グラフ順で判定）
- 各変種は focused から**そのブロックだけ** baseline の scale/zero point に戻す（先頭用・後続用の両モデル）。メモリ上で書き換え
- 評価点（結果を見る前に固定）: 日本語3ターン回答位置26、英語3ターン回答位置26（いずれも P12d の FP32 軌跡を teacher forcing）、
  点B（focused の履歴での「音」）、点A（1ターン目の分岐）、System Prompt 英「BANANA」/ 日「バナナ」の最初の回答トークン
- margin = logit[FP32 1位] − そのモデルでの最強の対抗（負なら FP32 1位を失った）。L2 は使わない

## 3. 非加法性

点B（focused −0.38 からの変化）

| 戻したブロック | 単独の効果 |
|---|---:|
| L0-13/その他 | +1.71 |
| L0-13/残差 | −0.80 |
| L0-13/RMSNorm補助 | +1.03 |
| L14-20/残差 | −0.36 |
| L14-20/RMSNorm補助 | −0.09 |
| L21-27/残差 | −0.15 |
| L21-27/RMSNorm補助 | −0.03 |
| **合計（加法予測）** | **+1.31 → 予測 +0.93** |
| **全部戻した実測** | **+3.73 → +3.35** |

BANANA は単独効果の合計 +0.14（予測 +0.43）に対し実測 +1.98。
**2.4〜4.2 もの差がブロック間の相互作用に由来する。** 1ブロックずつ戻す探索は、この問題には効率が悪い。

## 4. 読み方

- 層0-13 の残差の範囲変更は**有益**（戻すと margin 保持 49.5→31.5%、バナナ +6.00→+0.63）
- 層14-27 の範囲変更は、単独では点B にほぼ無関係
- 層2 MLP の2本は巨大値の発生源で、先頭と後続で範囲が 8000 級と 10 級に分かれる。ここを戻すと点A・点B は改善、対話全体の1位保持と BANANA は悪化。**この2本は単独でも影響が大きく、他ブロックとの相互作用の中心である可能性が高い**（未検証）
- 評価点52+4では、1位保持の差 1.9% が1点に相当する。**集計指標の小さな差は判断材料にならない**

## 5. 次の候補（判断が必要）

**A. このままブロック探索を続ける**（組み合わせ・相互作用を探す）。1変種約8分、組み合わせは急増し、
評価点も増やさないと差が検出できない。費用対効果は低いと見る。

**B. 目的に立ち返り、Host↔HTP の差の発生源を探す**（推奨）。
そもそもの問題は「Host QDQ の baseline は正しく答えるのに、実機（HTP）が壊れる」ことだった。
P12c で、Host と HTP の整数コードが最初に食い違う演算はまだ特定していない。層3 入口で実数誤差が跳ね、
その元が層2 MLP（`linear_20` が巨大値を作る）であることは今回分かったので、
**層2 MLP 周辺を C-8 に当たらない部分グラフとして切り出し、実機で同一入力比較**すれば、
Host 側の範囲調整ではなく **HTP で何が違うのか**を直接見られる。
