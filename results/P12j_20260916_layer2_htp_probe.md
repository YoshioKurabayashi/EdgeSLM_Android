# P12j — Host↔HTP の差の発生源：層2 MLP の中間値が「ほぼ3値」でしか表されていない

2026-09-16 / Qwen3-0.6B 28層 KV256 / 実機 Xperia 5 III（SM8350 / HTP v68）/ 入力は P12b step41（ホストのキャッシュ）

## 結論

**HTP の計算が大きく違うのではない。層2 MLP の2つのテンソルが、後続トークンに対して3〜4段の値でしか表現されておらず、
Host と HTP の ±1〜2 段の食い違いがそのまま信号の数十%になる。**

| テンソル | 役割 | scale | 後続トークンでの値 RMS | 使われたコード | ±1段以内の要素 | Host↔HTP 整数差 max | 実数誤差 |
|---|---|---:|---:|---:|---:|---:|---:|
| `linear_19` | up_proj 出力 | 0.00174 | 0.447 | 935 種 | 0.8% | 70 | 3.55% |
| `silu_2` | SiLU(gate) | 0.00095 | 0.203 | 471 種 | 0.1% | 101 | 2.12% |
| **`mul_41`** | **SiLU(gate)×up** | **0.105** | **0.091** | **14 種** | **93.5%**（65% が 0） | **3** | **16.83%** |
| **`linear_20`** | **down_proj 出力** | **0.113** | **0.121** | **8 種** | **86.4%** | **2** | **55.11%** |
| `add_26` | 層3 に入る残差 | 0.113 | 0.312 | 21 種 | 65.2% | 2 | 22.09% |

- `mul_41` と `linear_20` の scale は、**先頭トークンの巨大値**（`mul_41` −3488〜4211、`linear_20` 最大 8141、P12e 較正）に合わせて決まっている
- そのため**後続トークンでは値の RMS が1段とほぼ同じ**。`mul_41` は 65% の要素が 0、93.5% が ±1段以内という、実質3値の表現
- **整数の食い違いは最大でも2〜3段**。直前の `linear_19`・`silu_2` の実数誤差（2〜4%）が、粗い格子で丸められて 0 と ±1 の境界をまたぎ、
  `mul_41` で 16.8%、`linear_20` で 55.1% に跳ねる
- 層2 に入るまで（RMSNorm・attention・up/gate）は、整数差が数十〜数百段あっても**実数誤差は数%以内**（Softmax 7.9% が最大）

これは P12i で「点B を最も戻したブロック」として見つかった2本（層2 MLP の `mul_41` / `linear_20`）と一致する。

## 1. 方法

- 本番 QDQ から層2（`add_17` → `add_26`）を**そのまま**切り出した（qparam は作り直さない）。304ノード
- 入力: `add_17`（Q の手前の実数、ホストの層0-5 部分モデルから取得）/ past_k_2 / past_v_2 / cos / sin / attn_mask
- 観測版: 層2 内の QuantizeLinear 出力（uint16）＋ present_k_2/v_2。対照版: add_26 と present だけ
- 同じ入力で Host（ORT CPU）と実機（QNN HTP、strict=True・全ノード NPU）を実行し、グラフ順に整数コードを比較

### 等価チェック・対照

| 項目 | 結果 |
|---|---|
| ホスト: 観測版↔対照版の add_26・present | 最大差 0 |
| ホスト: 層2 部分モデルの add_26 ↔ 層0-5 部分モデルの add_26 | 最大コード差 0 |
| 実機: 観測版↔対照版の add_26 | 92/1024 要素が最大2段違う。**Host 比の実数誤差は 21.95%（対照）→ 22.09%（観測）で結論に影響なし** |
| 端末配布物の md5 | 一致（l2ctl / l2obs） |

### 途中で当たった QAIRT の制約（記録）

| 症状 | 原因 | 対処 |
|---|---|---|
| `Squash not possible for op add_17_QuantizeLinear` | グラフ入力の直後の Q を出力にした | 入力側の Q は観測しない |
| `Squash not possible for op present_v_2_DequantizeLinear` | グラフ出力の DQ の直前の Q を出力にした | 出力側の Q も観測しない |
| 実機 `Inconsistent output sizes` | QNN が **12本の観測出力を融合で消した**（EPContext は101本、QNN は89本） | QNN の出力89本だけで EPContext を包み直す |

消えた12本は、層2 の input_layernorm と post_attention_layernorm の**中核**（pow → mean → add → rsqrt → mul）。
HTP の `RmsNorm` に融合され、途中のテンソルが存在しない。q_norm/k_norm（pow_10/11）は融合されず残っていた。

## 3. これまでの結果との対応

| 記録 | 見えていたこと | 今回の説明 |
|---|---|---|
| P12c | 層3 入口で scale と実数誤差が跳ねる（add_17 3.14% → add_26 23.61%） | 跳ねているのは層2 MLP の `mul_41` → `linear_20` |
| P12c/P12d | 巨大値は先頭トークンの channel 35 だけ | その巨大値を作る `linear_20` と直前の `mul_41` の scale が、後続トークンを実質3値にしている |
| P12i | 点B を最も戻したのは層2 MLP の2本 | 同じ2本が Host↔HTP の差の増幅点 |
| P12b | 層6 の present_v が実機で 50% ずれる | 層2 で 22% ずれた残差が層3 以降に伝わる（層2 自身の present は 0.4〜0.8%） |

## 4. 次の候補

**先頭トークンの巨大値と、後続トークンの細かい値を、同じ scale で持たないようにする**のが本筋。
P12e の focused_split は168本を一括で変えて自由生成が崩れたが、今回、Host↔HTP の差の発生源は
**層2 MLP の2本とその下流の残差**だと特定できた。

有力な構成は、**固定の system prompt 部分の KV をホストの FP32 で事前計算して端末に持たせる**方式:

- 対話は必ず同じ system prompt（先頭 `<|im_start|>` を含む）から始まるので、**端末は位置0 を一度も計算しない**
  （固定 prefix の有効性は P10 で検証済み）
- すると端末のグラフは後続トークン専用の範囲だけでよく、先頭用/後続用の**2モデル切り替えが要らない**
- `mul_41` / `linear_20` と下流の残差を後続トークンの範囲にしても、端末では巨大値が来ないので飽和しない

P12e の hybrid（先頭だけ baseline の量子化モデル）でも崩れたので、成立するかは未確認。
**まず Host で「FP32 事前計算 prefix ＋ 後続用範囲」を多評価点＋自由生成で試し、通れば実機へ**進める。
