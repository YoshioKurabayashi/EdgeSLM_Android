# P12l — KV の量子化範囲を広げる：8bit の段でトレードオフになり、単独では改善しない

2026-09-16 / Qwen3-0.6B 28層 KV256 / Host CPU

## 結論

1. **KV 系252グループを全部広げると、baseline は大きく悪化した**（1位保持 85.7→78.6%、自由生成がユーザー発話のおうむ返し）。
2. **悪化の主因は uint8 の28グループ**。16bit の224グループだけ広げると 1位保持は 87.5%、margin 保持 41.7→51.8% と改善する。
   C-8 のため attention の act-act MatMul の右辺（GQA で複製した KV）は 8bit（255段）で、範囲を 2.55倍に広げると
   刻みが値の大きさに対して粗くなりすぎる。**既存の狭い範囲は、飽和と 8bit の分解能の妥協点だった。**
3. **それでも baseline を全面的に上回る構成は無い。** 16bit だけ広げた版でも、点B（+3.35→−0.67）と
   日本語 System Prompt（+4.45→+0.88）は悪化する。
4. 飽和を消すこと自体には効果がある（D1 の最小 margin −3.02 → −1.00）。ただし他の指標の悪化と相殺される。

## 1. 方法

- 対象: KV の値が流れる Q ノード448本（`kv_family.json`）→ scale 共有でまとめて **252グループ**
  （うち28グループは v_proj 出力など KV 以外の Q と scale を共有。中身は同じ値なので一緒に扱う）
- 範囲は**広げるだけ**: 新しい範囲 = 既存 ∪（FP32 観測 × 1.2）。狭めない
- 較正データは**評価に使わない**対話: P12d の long_ja / long_code / chat_long、計 **1,903トークン**（FP32 で 402秒、448本すべて観測）
- 広げた結果: 252グループすべてが拡大。倍率 中央値 1.53 / 最大 8.54。**uint8 は28グループ（最大 2.55倍）**

## 3. 読み方

- **C-8（act-act MatMul の右辺は 8bit）が、KV の表現力の上限を決めている。** 16bit のキャッシュで飽和を消しても、
  attention の直前で 8bit に落とす段が残る。そこを広げると刻みが粗くなり、狭いままだと頭打ちになる
- したがって「KV の範囲が狭すぎる（P12k）」は事実だが、**単純に広げて直る問題ではない**
- Host 側の qparam をいじる実験（P12e / P12i / P12k / P12l）は、**どれも baseline を全面的に上回らなかった**。
  ある評価点を良くすると別の点が悪くなる形が繰り返し出ている

## 4. 次

Host 側の範囲調整の探索はここで止める。本来の問題は **Host は正しく答えるのに実機が壊れる**ことであり、
P12j で発生源（層2 MLP の `mul_41` / `linear_20` が後続トークンに対して実質3値）まで特定できている。
**その2本だけを後続トークンの範囲にした層2 部分モデルを実機で走らせ、add_26 の Host↔HTP 誤差（現在 22.09%）が
下がるかを直接測る**のが、最も安い決定的な実験（ビルド15分程度）。
