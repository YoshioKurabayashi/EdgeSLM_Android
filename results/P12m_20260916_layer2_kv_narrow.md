# P12m — 層2 MLP の2本だけ後続範囲にすると、add_26 の Host↔HTP 誤差が 22%→9% に下がった

2026-09-16 / Qwen3-0.6B 28層 KV256 / 実機 Xperia 5 III（SM8350 / HTP v68）/ 入力は P12j と同じ step41（ホストのキャッシュ）

## 結論

**P12j で特定した層2 MLP の `mul_41` / `linear_20` の2本だけを後続トークン用の範囲に差し替えると、
add_26 の Host↔HTP 実数誤差は 21.95%（baseline）→ **8.61%**（narrow）に下がった。**
Host 側の指標は一切変えず、実機の差だけを見た一発勝負の実験。P12l までの「Host の qparam をいじっても
baseline を上回らない」という結論は、KV系252グループの調整には当てはまるが、
今回のように**発生源そのもの（P12jで特定した2本）に絞った調整**には当てはまらない。

## 1. 方法

- P12j の層2部分モデル（`work/q3_l2/l2ctl_qdq.onnx`、add_17→add_26 をそのまま切り出した3出力版）を複製し、
  `mul_41_scale`/`mul_41_zero_point`・`linear_20_scale`/`linear_20_zero_point` の4つの initializer だけを書き換え
- 新しい scale/zero point は **P12e で既に較正済みの「後続トークン」範囲**をそのまま流用（新規較正はしていない）。
  `results/P12e_20260915_temporal_qdq/build_audit.json` の `later` フェーズ・margin 1.5 の値
  （観測範囲を1.5倍に拡張してフィット）

| テンソル | 旧 scale/zero（先頭込みの既存範囲） | 旧の表現範囲 | 新 scale/zero（後続専用） | 新の表現範囲 |
|---|---|---|---|---|
| mul_41 | 0.10498359 / 29393 | −3085.8 〜 3794.3 | 0.00037499 / 39798 | −14.92 〜 9.65 |
| linear_20 | 0.11333263 / 1489 | −168.8 〜 7258.5 | 0.00017944 / 21833 | −3.92 〜 7.84 |

- 他はすべて P12j と同一: 入力・グラフ構成・add_26 自身の qparam・ビルド手順（qairt-converter → context binary → EPContext ラップ）
- Host（ORT CPU）で baseline / narrow それぞれの add_26 を計算し、同じ入力を実機（QNN HTP, strict=True）で走らせて比較

## 2. 結果

| 変種 | add_26 Host↔HTP 実数誤差 | 整数コード差 max |
|---|---:|---:|
| baseline（既存範囲、今回の実測） | 21.95% | 2 |
| baseline（P12j の記録値、参考） | 22.09% | 2 |
| **narrow（mul_41/linear_20 だけ後続範囲）** | **8.61%** | **1** |

baseline の実測値（21.95%）は P12j の記録値（22.09%）とほぼ一致しており、実機実行の揺らぎの範囲内。
narrow は誤差・整数コード差の両方で改善した。

## 3. 読み方

- P12j の見立て（scale が先頭の巨大値に引きずられ、後続トークンでは実質3〜4値しか表現できていない）が、
  Host↔HTP 誤差の主因だったことが、この2本を直すだけの変更で裏付けられた
- P12l で確かめた「KV系252グループを広げても効かない（C-8の8bit段が上限）」問題は、この2本には無関係
  （mul_41/linear_20 はどちらも act-act MatMul の右辺ではなく、C-8 の制約を受けない）
- 8.61% まで下がったが 0 ではない。層2 の入口・attention 側（P12j で実数誤差2〜8%だった箇所）や、
  層2 MLP の手前2本（`linear_19`/`silu_2`、実数誤差3〜4%）が積み上がった分は残っている

## 4. 次

安く決定的な実験（ビルド15分）で改善を確認できた。P12l の見立てどおり、**28層本番ビルド（136分）に進む価値がある**。
ただし今回検証したのは層2単体・固定入力1点（step41）のみ。本番へ進む前に、

1. 同じ「後続範囲」を28層全体の該当2本×28層分（もしくは全層同型の2本ずつ）に適用したQDQを作る
2. P12b/P12d の対話評価点・自由生成で崩れないか（先頭トークンでは既存範囲のままにする必要がある点はP12eと同じ課題）
3. 先頭/後続の2モデル切り替えが必要か、それとも後続範囲だけで先頭トークンも許容範囲に収まるかを確認

を先に Host で通してから実機へ、という P12j の元々の道筋に戻る。
