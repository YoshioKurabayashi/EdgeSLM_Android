# P12r — linear_20 の range sweep：安定して合格したのは4xだけ、range調整はここで打ち切り

2026-09-16 / Qwen3-0.6B 28層 KV256 / Host CPU

## 結論

**層2 `linear_20`（down_proj出力）のrange幅を1x(narrow)〜8xまで7点で振った結果、
teacher forcingと自由生成の両方で一貫して安定したのは4xだけだった。** 2x/3x/3.5x/3.75x は
それぞれ異なる形で自由生成が崩れ（文字化け・重複・話題回避など）、8xはバナナ/BANANAが急落した。
**「狭いほど良い／広いほど良い」という単純な単調関係ではなく、4x付近に孤立した安定点がある。**

4xを層2部分モデルで実機評価した結果（P12s）は add_26 の Host↔HTP誤差 21.95%→18.67%と
改善幅が小さく、事前に決めた「15%以下なら前向き」の基準に届かなかった。
**range調整によるアプローチはここで打ち切り、次はoutlier channel特化処理など別方式に移る。**

## 1. 方法

- `mul_41` は baseline 固定。`linear_20` の scale/zero だけを、P12e 後続較正の観測値
  （margin=1.5 のときのlo/hi = [-2.6117844581604004, 5.228030681610107]）に対して
  margin を 1.5×N（N=1〜8）でスケールして段階的に振った
- 位置0はbaselineのまま、位置1以降だけ各rangeのモデルを使う2モデル切り替え（P12oと同じ枠組み）
- 評価は毎回: 対話評価点のteacher forcing比較（top1保持・margin保持・KL・点B・点A・BANANA・バナナ）＋
  元の日本語3ターンの自由生成。**自由生成を最優先の判定基準**とする（ユーザーの方針）
- 二分探索的に進めた: 2x/4x/8xを先に見て（4xが唯一クリーン）、4xの実機効果が小さかった（P12s）ため
  3x→3.5x→3.75xで4xの下側の境界を追い込んだ

## 3. 読み方

- **集計指標（top1保持・KL・バナナ等）は自由生成の健全性を予測しない。** 3.75xは全指標で最良
  （top1保持87.5%、KL0.173、バナナ+5.77）なのに自由生成は失敗している。逆に4xは点B が負なのに
  自由生成は完璧だった
- **失敗の形は range ごとに異なる**（文字化け・重複・話題回避）。これは同じ「量子化誤差」が
  自己回帰生成のどこかで増幅され、たまたまどのトークンの選択に影響するかが range ごとに
  変わっているためと考えられる。連続的に改善する滑らかな関数ではなく、**安定/不安定が入り組んだ
  地形**になっている
- **4xだけが、7点中で唯一「文字化けなし・重複なし・指示無視なし」を満たした。** これが
  「Host能力を壊さない最小range」の実測結果

## 4. 次

**range調整（rangeの幅だけを動かすアプローチ）はここで打ち切る。** 4x実測（P12s: 18.67%、
目標15%未達）を踏まえ、次はP12oで挙がっていた方向に移る:

- outlier channel（先頭トークンだけ極端に大きい値を持つチャンネル）を、range全体ではなく
  個別に特殊扱いする方式（channel split、SmoothQuant系のスケール移動、該当チャンネルだけ
  高精度化など）
- あるいは P12k の「先頭トークンのKVをFP32事前計算して端末に持たせる」方式との組み合わせ
