# P12y — position45・layer14のV局所swap：誤差の向きも含めて、この1点では判定は動かない

2026-09-16 / Qwen3-0.6B 28層 KV256 / Host CPU

## 結論

P12xで見つけた「position45・layer14のVで、oracleだけL2誤差が71.7%まで跳ね上がる」という
局所異常が、実際に点Bの判定を悪い方向へ動かしているかを、FP32の正しい軌跡にこの1点だけを
差し替えて実際に順伝播させ確認した。**期待していた「baseline小さい、4x小さい、oracle強く悪方向」
というパターンは見られず、3条件とも判定への効果はほぼ無視できる大きさで、oracleはむしろ
良化方向（+0.0188）だった。** P12wのadd_26単体swapと同じ結論を、KVの1点でも再確認した形。

## 1. 方法

- 点B（80トークン）をFP32モデルでteacher forcingし、position45のところで
  `past_v_14`の新規スロット（8×128=1024次元）だけを、P12xで採取済みの
  baseline/4x/oracleの値に差し替え、position46以降もFP32モデルで継続した
- 判定位置79（最後のトークン）のlogitsから、FP32自身の1位トークン（id=78685）を基準にmarginを計算
- 差し替えなし（純粋なFP32）を対照として、Δmargin = margin_条件 − margin_FP32 を比較した

## 2. 結果

| 条件 | margin | Δmargin(FP32比) |
|---|---:|---:|
| FP32（対照） | +4.6165 | 0.0000 |
| baseline | +4.6111 | −0.0055 |
| 4x | +4.6120 | −0.0045 |
| **oracle** | +4.6353 | **+0.0188** |

3条件ともΔmarginは±0.02以内。FP32自身のmargin（+4.6165）と比べて無視できる大きさ。
oracleの効果は他の2条件より絶対値が大きいが、**方向は良化（プラス）**であり、予想（悪化）と逆。

## 3. 読み方

- **P12xで見つかった大きな幾何的異常（L2誤差71.7%）は、判定への直接的な因果効果としては
  ほぼゼロだった。** 「誤差の大きさ」と「判定への実際の効果」がここでも一致しなかった
- これはP12wのadd_26単体swap実験と同型の結論: **単一の(position, layer, テンソル)点を
  差し替えるだけでは、点Bの失敗を再現・説明できない**
- 3回にわたって（add_26単体→KV1点）「局所的な1点の操作では効果が出ない」という結果が
  続いており、点Bの失敗はより**分散的・複合的な効果**（多くのposition・layerにわたる
  差の組み合わせ、あるいはK/V誤差では捉えられない別の経路）に起因する可能性が高まっている

## 4. 次

ユーザーの事前計画に従い、局所swapでは効果が見られなかったため、**大域的なK-only/V-only
swap実験**に進む（未着手・要承認）:

- oracle K + oracle V（対照、oracleそのもの）
- baseline K + oracle V
- oracle K + baseline V
- baseline K + baseline V

全position・全28層にわたってKだけ、あるいはVだけを丸ごと差し替えることで、
KとVどちらの「全体としての差」が判定を動かすかを特定する。
