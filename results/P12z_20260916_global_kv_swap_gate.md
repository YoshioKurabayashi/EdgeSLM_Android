# P12z — 大域K/V swapゲート試験：K・Vどちらも単独で判定を反転させる（ゲートA該当）

2026-09-16 / Qwen3-0.6B 28層 KV256 / Host CPU

## 結論

**KV状態（全position・全28層）を丸ごと入れ替えるゲート試験の結果、KだけでもVだけでも
単独の交換で判定が負→正に反転した。** これまで3回連続で失敗していた局所swap（P12w: add_26
単体、P12y: KVの1点）とは対照的な結果で、「KVキャッシュの累積差そのものが判定を動かしている」
という仮説が強く支持された。事前に決めたゲート基準では**A（KまたはVの片方の交換だけで大きく
回復する）に該当**し、次はlayer block × K/Vへ分解する探索に進む。

## 1. 方法

- 点B（80トークン）を oracle モデル・baseline モデルそれぞれで独立に teacher forcing し、
  判定位置79の直前（position 0-78）までのKVキャッシュ（全28層のK・V）を保存した
- **最終step（判定位置79のトークンをfeedする処理）は常にoracleモデルに固定**し、
  そこへ入力する過去のK・Vだけを、oracle自身のものとbaselineのもので以下の4通りに
  組み合わせて与えた:

  | K | V | 意味 |
  |---|---|---|
  | oracle | oracle | 失敗側対照（oracle自身） |
  | baseline | oracle | Kをbaseline化すると救えるか |
  | oracle | baseline | Vをbaseline化すると救えるか |
  | baseline | baseline | 成功側対照（KV両方baseline化。最終step計算自体はoracle固定） |

- 判定基準はP12w/P12x/P12yと同じ、FP32自身の1位トークン（id=78685）に対するmargin

## 2. 結果

| K | V | margin |
|---|---|---:|
| oracle | oracle | −1.0210 |
| **baseline** | oracle | **+0.8388** |
| oracle | **baseline** | **+1.1808** |
| baseline | baseline | +3.1374 |

## 3. 読み方

- **KだけでもVだけでも、単独の交換で判定が負→正に反転する。** 事前ゲート基準の
  **パターンA**（片方の交換だけで大きく回復）に該当する
- Vの方がKよりわずかに効果が大きい（+1.18 vs +0.84）が、両方とも明確に効いており、
  「Vが主犯でKは無関係」というほど非対称ではない
- 両方をbaseline化すると最も強く回復する（+3.14、baseline自身の実際のmargin +3.35に近い）が、
  これは単純な加算（+0.84 + 1.18 = 2.02 の少し上）以上の相乗効果がある可能性がある
- **重要な対比**: P12w（add_26という1点の値）・P12y（KVの1点、position45/layer14のV）は
  どちらも局所的な操作で効果がほぼゼロだった。今回は「全position・全28層にわたる差の
  合計」を一括で操作したことで初めて効果が見えた。**個々の点では無害に見える誤差が、
  積算されると判定を動かす**という構造が確認できた

## 4. 次（事前に決めたゲートに従う）

パターンA（KまたはVの片方の交換だけで大きく回復）に該当するため、**layer block × K/Vへ
分解する探索に進む**:

1. 全28層をいくつかのブロック（例: L0-6 / L7-13 / L14-20 / L21-27、あるいはP12xで異常が
   見えたL14周辺を細かく）に分け、各ブロックだけK/Vをbaseline化した場合の回復度を見る
2. どのブロックが単独で最も回復に寄与するかを特定する
3. 必要ならP12xの「位置45・層14」の局所異常が、大域的な文脈の中でも重要な役割を持つか
   （単独では無害だが他のブロックと組み合わさると効くのか）を確認する
