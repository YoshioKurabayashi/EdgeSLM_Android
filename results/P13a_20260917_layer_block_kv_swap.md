# P13a — layer block × K/V分解：Vは分散型で加法的、Kは強い相互作用（L0-6単独では悪化）

2026-09-17 / Qwen3-0.6B 28層 KV256 / Host CPU

## 結論

P12z（大域K/V swap）の続きとして、28層を4ブロック（L0-6/L7-13/L14-20/L21-27）に分け、
各ブロック・各K/Vだけをbaseline化した場合の判定margin回復度を測定した。**KとVで構造が
全く異なる**:

- **V**: L7-13とL14-20が大きく正方向に寄与（+1.27, +1.88）し、L0-6はほぼ無関係（−0.05）、
  L21-27はやや負（−0.50）。ブロック単位のΔmargin合計（+2.605）は全V一括swap（+2.202）に
  近く、**分散型（複数ブロックがそれぞれ効く）**と判断できる
- **K**: **L0-6単独では悪化する（−1.54）のに、全K一括では改善する（+1.86）**という、
  単純な合計では説明できない強い相互作用がある（ブロック合計 −0.744 は全K一括 +1.860 と
  符号すら合わない）

事前ゲート基準では、Vは「複数ブロックがそれぞれ効く → 分散型」、Kは「個別ブロックでは
弱い/逆方向なのに全体交換だけ強い → block間相互作用」に該当する。

## 1. 方法

- P12zと同じ枠組み。final-stepはoracleモデルに固定し、判定位置79直前（position 0-78）の
  過去KVキャッシュを、28層を4ブロックに分けてbaseline化した:
  - L0-6（層0-6）/ L7-13（層7-13）/ L14-20（層14-20）/ L21-27（層21-27）
  - 各ブロックについて、K側だけbaseline化／V側だけbaseline化の8変種
- 対照（oracle基準）margin: −1.0210（P12zと一致）

## 3. 読み方

- **V側**: L7-13・L14-20が主要な寄与元で、L0-6はほとんど無関係、L21-27はむしろ負の寄与
  （baseline化すると悪化する）。ブロック合計が全体効果とおおむね一致するので、**分散的だが
  概ね加法的**と考えてよい。L14-20が最大の寄与という点は、過去の記録（層12-14のV飽和）とも
  方向性は一致するが、L7-13も同程度に重要であり、L14-20だけに絞るのは早計
- **K側**: **L0-6を単独でbaseline化すると、oracle対照（−1.02）よりさらに悪化する（−2.56）。**
  しかし全28層のKを一括でbaseline化すると改善する（P12z: +0.84）。つまり、**L0-6のK差だけを
  戻すことは、単独では有害だが、他のブロック（特にL7-27）のK差と組み合わさると初めて
  有益になる**という、強い非線形の相互作用がある
- この構造は、L21-27のKがほぼ中立（−0.05）であることも踏まえると、**K側の「有害さ」と
  「有益さ」は特定の層だけでは決まらず、複数ブロックの組み合わせ方に依存する**ことを
  示している。Vよりも扱いが難しい

## 4. 次

Vは分散型なので、L7-13とL14-20をさらに二分して絞り込む価値がある。
Kは相互作用が強いため、単純な二分探索ではなく、**2ブロックの組み合わせ**（例:
L0-6+L7-13、L0-6+L14-20、L0-6+L21-27など）を試して、どの組み合わせでL0-6の「有害さ」が
「有益さ」に転じるかを特定する必要がある。
