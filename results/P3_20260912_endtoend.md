# P3: end-to-end の精度と容量（本物の Qwen2.5-0.5B）

| 項目 | 内容 |
|---|---|
| 実施日 | 2026-09-12 |
| 対象 | Qwen2.5-0.5B-Instruct の **先頭2層 + 埋め込み(151,936語彙) + lm_head**（prefill / seq 16） |
| 較正 | 実テキスト 14系列のトークンID |
| 評価 | **較正とは別の文** 11系列 × 16トークン = 176 位置 |
| 判定 | **載る。しかし C-8 の代償で次トークン予測の半分が変わる** |

---

## 1. 結論

| | top-1 一致 | top5 重なり | KL | fp32のtop1が何位か | logits相対L2 |
|---|---:|---:|---:|---:|---:|
| **A16W8 素**（v68 では**動かない**） | **85.2%** | 88.8% | 0.024 | **1.20位** | 6.79% |
| **A16W8 + attentionのみA8**（v68 で動く） | **50.0%** | 59.0% | 0.556 | **20.64位** | 32.59% |

**v68 で動かすために、次トークン予測の一致率が 85% から 50% に落ちる。**
fp32 が1位に選ぶトークンは、量子化後には平均 **20.6位** まで落ちている。

しかもこれで**まだ2層**である。24層ではさらに開く。

### 層1枚の測定との対応

| 段階 | 指標 | A16W8素 | C-8回避 |
|---|---|---:|---:|
| 層1枚 | 出力の相対L2 | 5.50% | 30.39% |
| **2層 end-to-end** | **top-1 一致** | **85.2%** | **50.0%** |

層の L2 誤差で見た比（5.5倍）は、end-to-end でも同じ向きに出た。
**「層の L2 が大きいだけで実害があるとは限らない」という留保は、今回は外れなかった。**

## 2. 容量: 440MB の本物の LLM が NPU に載った

```
モデル : Qwen2.5-0.5B の 埋め込み + 2層 + lm_head
QDQ    : 438 MB
DLC    : 418 MiB
context: 419.67 MiB
EPContext ONNX: 440 MB
```

端末での結果:

```
backend : QNN HTP - EPContext - all nodes
strict  : True                        ← 全ノードが HTP。CPU に落ちたノードはゼロ
io      : input_ids [1,16] int64 -> logits [1,16,151936] float32
ロード  : 4.15 秒
OrtRun  : median 17.42 ms / p90 18.40 / min 14.97 / max 18.87 (n=10)
warmup  : 26.6 → 15.9 → 18.1 ms
温度    : NPU 32.1℃（10回程度では上がらない）
MemAvailable: 2.91 GiB → 3.33 GiB（ロード前後で減っていない＝PD側に載っている）
```

**151,936語彙の埋め込み Gather も、[1,16,151936] の lm_head も、HTP に載る。**

### PD メモリの上限について

事前調査では「v68 で数百MB級の context がロード失敗した事例」（#18410 等）があり、
**698MB が上限か**という誤読を一度している（要件定義書 3.3.2節）。
今回 **419.67 MiB の context binary が実機でロードできた**ので、
少なくともこの規模までは問題ない。**自前の実測値が1点得られた。**

## 3. 24層は測れなかった（ツールの制限）

フル24層（fp32 1.98GB）は **S4 の量子化で止まった**。

```
EncodeError: Failed to serialize proto
```

**onnxruntime の量子化器が 2GB を超えるモデルを保存できない。**
`use_external_data_format` は既定で True になっていたが、それでも内部のどこかで
単一 protobuf にまとめようとして失敗する。**v68 の制約ではなくホスト側ツールの限界**。

対処案（未実施）: モデルを層ごとに分割して個別に量子化する / ORT を上げる /
別の量子化経路（ExecuTorch）を使う。P4 で扱う。

### その過程で踏んだ罠

**`quant_pre_process` が 2GB 超で 47バイトの空モデルを出力し、例外を出さなかった。**
気付いたのは後段の `get_qnn_qdq_config` が `StopIteration`（opset_import が空）で
落ちたときで、**原因から遠く離れた場所**だった。

→ パイプラインに**成果物の健全性を確かめる門**を入れた
（`preprocess._assert_sane`: ノード数と opset が空なら即座に落とす）。
S4 にも同じ門を足した。

**これで「ファイルができた＝成功」と読んだ失敗は4件目**:
`dd` のサマリ行 / `Cache binary ... copied to` / `adb push` の成功報告（次節）/ 本件。

## 4. また MSYS のパス変換に嵌まった

440MB の push が「成功」と報告されたのに、端末にファイルが無かった。

```
adb push ... /sdcard/Android/data/.../models/ops/
→ 1 file pushed, 0 skipped. 42.7 MB/s (440060904 bytes in 9.817s)
→ 端末側に存在しない
```

真因は Git Bash のパス変換で、宛先が `C:/Program Files/Git/sdcard/...` に化けていた。
`scripts/run_runner.sh` は `MSYS2_ARG_CONV_EXCL` を設定しているので正しく動くが、
**adb を手で叩いたときに設定を忘れた**。環境構築記録 4章に記録済みの罠を再度踏んだ。

→ 手で adb を使うときも `export MSYS2_ARG_CONV_EXCL='...;/sdcard;/storage'` を付ける。

## 5. これが意味すること

### 5.1 v68 で Qwen2.5-0.5B は「動く」が「使える」かは別

| 問い | 答え |
|---|---|
| op は載るか | **載る**（P2b で 22/22） |
| 本物の重みで動くか | **動く**（層1枚 0.958ms、2層+埋め込み 17.4ms） |
| 容量は足りるか | **420MB の context はロードできた**。24層は未測定 |
| **精度は足りるか** | **足りない**（2層で top-1 一致 50%） |

**残った壁は精度だけで、その原因は C-8 という v68 のアーキテクチャ制約に帰着する。**

### 5.2 未決事項#6（端末追加調達）の判断材料

要件定義書は「8 Gen 2以降の端末を追加調達するか」の判断を **P3 完了時点**まで
遅らせるとしていた。材料が揃った。

| | SD888 (v68) | 8 Gen 2以降 (v73+) |
|---|---|---|
| 16bit の act×act MatMul | **不可**（C-8） | 可 |
| attention スコアの量子化 | 8bit 強制 | 16bit 可 |
| **2層 end-to-end の top-1 一致** | **50.0%** | **85.2% 相当**（A16W8素の測定値） |
| weight sharing（prefill/decode 共有） | 不可（v73+） | 可 |
| 容量（420MB context） | **実測で OK** | OK |

**v68 固有の制約が2つ（C-8 / weight sharing）とも v73 で解ける。**
一方 SD888 でも「動く」ところまでは到達しており、**要素技術の習得という目的は
果たせている**。追加調達は「精度を伴う実用形まで見たいか」次第。

### 5.3 まだ測っていないこと

- **24層 end-to-end**（ツール制限。2層からの外挿はしていない）
- **decode（AR-1）と KVキャッシュを繋いだ生成**
- **実機上の数値精度**（ここまでの精度はすべてホスト CPU での QDQ シミュレーション。
  HTP の演算順序・丸めの違いは含まれていない。**実機はこれより悪くなりうる**）
- **較正を増やした場合**（14系列は少ない。ただし C-8 の機構は較正では直らない）

## 6. 次

```
⬜ 実機での精度            runner v0.3（出力を返す機能）が要る → ビルド1回
⬜ 24層                   量子化を層分割するか、別経路を試す
⬜ decode + KVキャッシュ   P4 の本題
⬜ 未決事項#6 の判断        上記を踏まえて
```

**最優先は実機での精度**。ここまでの数字はすべてホスト上のシミュレーションで、
**「実機で測っていない」という留保が付いたまま**である。P1〜P2b で
「ホストで通ることと端末で動くことは別」を3回学んだ以上、精度も実機で確かめる。
