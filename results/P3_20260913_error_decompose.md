# P3: 実機の誤差を「量子化」と「QNN-HTP 追加分」に分解する

| 項目 | 内容 |
|---|---|
| 実施日 | 2026-09-13 |
| 狙い | 実機の誤差のうち、**どこまでが量子化で、どこからが実行系の違いか** |
| 方法 | 中間に「ホスト CPU で同じ QDQ モデルを走らせた結果」を挟んで差分を取る |
| 判定 | **実機差が量子化より大きい場合がある。ただし HTP が本質的に不正確なわけではない** |

---

## 1. 方法

これまで「fp32 vs 実機」しか見ておらず、誤差の内訳が分からなかった。

```
fp32  ──[ 量子化誤差 ]──>  ホストQDQ  ──[ QNN-HTP 追加分 ]──>  実機
```

**同じ QDQ モデル・同じスケールを使う**ので、後半の差分は**実行系の違いだけ**になる。
（`app/pipeline/error_decompose.py`）

### 測り方の注意（2026-09-13 に指摘を受けて訂正）

**① 分母を揃える。** 当初 `‖a-b‖ / ‖a‖` としていたため、量子化誤差は `/‖fp32‖`、
実機差は `/‖ホストQDQ‖` と**分母が違っており、直接比較できない数字を並べていた**。
現在は**すべて `/‖fp32‖`** に揃え、絶対 L2 も併記している。

**② 3つの値は加算関係にない。** L2 はベクトルの距離なので `9.31 + 13.25 ≠ 16.11`
は当然である。2つの誤差ベクトルが直交していれば**二乗和の平方根**が合計に一致する。
実測ではほぼ一致した（後述）＝**量子化誤差と実機差はほぼ無相関**。

**③「HTP の誤差」と呼ぶのは狭すぎる。** QNN EP は ONNX をそのまま逐次実行するのではなく、
QNN graph を構築して HTP 向けに compile/finalize する。この差分には HTP の積和精度・
丸めだけでなく、**QNN への lowering・op fusion・QDQ 境界の変更・requantization・
layout 変換・kernel 選択**が含まれうる。本書では **QNN-HTP 追加分**と呼ぶ。

---

## 2. 結果

**分母はすべて `‖fp32‖`。** 括弧内は絶対 L2。

| モデル | 量子化 | **QNN-HTP 追加分** | 合計 | 二乗和の平方根 |
|---|---:|---:|---:|---:|
| **重み固定 MatMul 1個**（A16W8） | 0.92% | **0.11%** | 0.92% | 0.92% |
| 活性化×活性化 MatMul | 2.44% | **1.98%** | 2.50% | 3.14% |
| Qwen 層1枚（`u16×u8`+入替） | 9.31% | **13.25%** | 16.11% | 16.19% |
| Qwen 2層 e2e（`u16×u8`+入替） | 9.90% | **20.21%** | 22.11% | 22.51% |

**二乗和の平方根が合計にほぼ一致する**（16.19 vs 16.11、22.51 vs 22.11）ため、
**量子化誤差と実機差はほぼ直交**している。つまり両者は別々の要因である。
（活性化×活性化 MatMul だけ 3.14 vs 2.50 とずれており、こちらは部分的に打ち消し合っている。）

### 分かったこと

**① HTP は本質的に不正確ではない。**
重み固定の MatMul 1個なら実機差は **0.11%** しかない。
つまり Qwen 層の 13.25% は **HTP の基本性能ではなく、あのグラフ固有の何か**である。

**② 実機差は層を重ねると増える。**
1層 13.25% → 2層 20.21%。誤差が層をまたいで積み上がっている。

**③ 「実機側が一定の下限を作る」という仮説は外れ。**
方式によって 20.21% と 31.98% に変わる。粗い量子化の方が実機差も大きい。

**④ 前回の解釈を訂正する。**
前回「量子化誤差を小さくした方が実機での低下が大きい（-3.4pt vs -17.6pt）」と書き、
「HTP 側の下限が顔を出す」と解釈した。**分解してみると逆で、HTP 誤差自体は
粗い方式の方が大きい**（31.98% > 20.21%）。top-1 の低下が小さく見えたのは、
**元々の精度が低く、追加の誤差では argmax がもう変わらない飽和**である。

→ **指標を変えると話が変わる。** L2 で見るか top-1 で見るかで結論が反転した。

**⑤ 実機は完全に決定的。**
同じモデル・同じ入力を2回実行した結果は**ビット単位で一致**（最大絶対差 0）。
13.25% はノイズではなく**系統的なズレ**であり、原因を特定できる余地がある。

## 3. 測定の失敗（記録として残す）

**P2b で作った自作 op モデルを精度測定に流用したのは誤りだった。**

`block_real`（自作の Transformer 1ブロック）の誤差は **0.01%** と出たが、これは無意味である。
自作モデルの重みは `N(0, 0.05)` の乱数で、attention と FFN の寄与が小さい。
出力は残差接続の `x` にほぼ支配され、**誤差が薄まって見える**。

```
出力 = x + attention(x) + FFN(x)
       ↑ここが支配的        ↑誤差はここに乗る
```

自作モデルは**「op が載るか」を見るために**作ったもので、精度を測る設計になっていない。
**道具を目的外に使うと、静かに間違った数字が出る。**

同じ理由で、以下の数字も参考程度に留める:

| モデル | 量子化 | QNN-HTP 追加分 | 備考 |
|---|---:|---:|---|
| softmax | 0.006% | 0.169% | 単独なので比較的信頼できる |
| **matmul_act**（活性化×活性化） | 2.44% | **1.98%** | 重み固定 MatMul の **18倍** |
| rmsnorm_real | 0.36% | 0.24% | |
| attention（自作） | 6.09% | 3.11% | 残差なしなので多少は意味がある |
| ~~block_real~~ | ~~0.01%~~ | ~~0.01%~~ | **残差に薄められて無意味** |

唯一はっきり言えるのは **`matmul_act`（活性化×活性化 MatMul）の実機差が
重み固定 MatMul の 18倍**という点である。

**ただしこれで Qwen の 13.25% を説明したことにはならない。**
単体で 1.98% しかないものが、どう 13% になるのか——考えられるのは
**softmax による増幅**である。実際にスコアの L2 誤差 0.49% が
softmax 後に 62.8% になる例を既に見ている（`P3_20260912_accuracy_layer1.md`）。
**「1.98% だから無関係」でも「1.98% が原因」でもなく、増幅経路を測らないと分からない。**

## 4. 現時点の理解

```
HTP の基本演算精度        問題ない（重み固定 MatMul で 0.11%）
  ↓
活性化×活性化 MatMul      実機差が 18倍（1.98%）——ただしこれだけでは 13% を説明できない
  ↓
softmax による増幅？       スコアの微小差が確率分布を大きく変える経路は実在する
                          （量子化では L2 0.49% → softmax 後 62.8% を観測済み）
  ↓
layer 0 の極端なレンジ     スコア幅 1677 は他層の 8〜16倍。微小な実装差に敏感なはず
  ↓
層を重ねる                誤差が積み上がる（1層 13.3% → 2層 20.2%）
```

**まだ仮説である。** 確かめるには**本物の Qwen の層を途中で切った部分モデル**で、
少なくとも次の5点の実機値を取る必要がある:

```
④ QK MatMul 直後   ⑥ Softmax 直後   ⑦ P×V 直後   ⑨ Residual 加算後   ⑬ Layer 出口
```

**Attention 出口だけでは粗い。** 例えば「QK 2% / Softmax 18% / P×V 17%」なら
**増幅が真因**、「QK 2% / Softmax 3% / P×V 15%」なら **P×V 側の混合精度 MatMul**
が本命、と切り分けられる。

**残差の前後を必ず両方測る**ことも要る。今回 `block_real` で踏んだとおり、
branch の誤差が 20% でも残差加算後は 2% に見えることがある
（精度が良いのではなく**隠れている**だけ）。

## 5. 次

```
⬜ QNN CPU backend との比較   fp32 → ORT-QDQ → QNN CPU → QNN HTP と段を増やす。
                              QNN CPU は QNN operator の reference 実装なので、
                              「ORT-QDQ と QNN semantics の差」と「HTP 固有」を分けられる。
                              **部分モデルを大量に作るより先に1回試す価値がある**
⬜ 本物の Qwen の部分モデル    ④QK / ⑥Softmax / ⑦P×V / ⑨Residual / ⑬Layer出口 の5点
⬜ 24層 end-to-end
⬜ decode + KVキャッシュ（P4）
```

**この切り分けの価値**: 「ホスト上で量子化を詰めれば実機も良くなる」とは限らないことが
分かった。ホストで 9.9% まで詰めても実機は 22.1% で、差の大半は HTP 側にある。
**ホストでの作り込みには、実機で確かめない限り意味が付かない。**
