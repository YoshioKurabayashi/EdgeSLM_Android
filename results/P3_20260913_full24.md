# P3: 24層への到達と、そこで現れた壁（massive activations）

| 項目 | 内容 |
|---|---|
| 実施日 | 2026-09-13 |
| 結果 | **2GB 問題は解決した。しかし 24層は数値的に壊れる**（端末以前に**ホストで**壊れる） |
| 原因 | 残差ストリームの **massive activations**。量子化の既知の難問 |

---

## 1. 2GB 問題は解決した

### どの 2GB だったのか

「seq=1 にすれば解決」と考えたのは誤りだった（**重みは seq に依存しないので減らない**）。
指摘を受けて実際に特定したところ、場所はここだった:

```
quantize_static
  → update_opset_version
    → onnx.version_converter.convert_version
      → model.SerializeToString()      ← ここで EncodeError
```

**16bit 量子化は opset ≥ 21 を要求するため、ORT が opset 18 → 21 の自動変換を行う。**
その変換が **fp32 の全重み（2.52GB）をメモリ上で 1つの protobuf にシリアライズ**しようとして
protobuf の 2GB 制限を超えていた。

| 候補 | 該当 |
|---|---|
| A. ONNX protobuf > 2GB | 該当するが external data で回避済み |
| **B. ORT 側の処理** | **これ。ただし「optimizer」ではなく opset 変換ステップ** |
| C. QNN context binary が巨大 | 該当しない（後述） |
| D. Android のロード | 未到達 |

**出力である QDQ モデルは 0.63GB**（630.2M 要素の int8）で、2GB を大きく下回る。
**サイズの問題ではなく、中間処理の問題だった。**

### 解決策: 最初から opset 21 で export する

変換が不要になるので、巨大 protobuf のシリアライズが起きない。

```
export opset 21  →  quant_pre_process  →  quantize_static  →  QDQ 767MB
```

**24層の量子化が通った**（2分17秒）。

### export の健全性を確認した

| 確認 | 結果 |
|---|---|
| opset 21 の fp32 ONNX vs HuggingFace PyTorch | **最大絶対差 9.7e-05 / 相対L2 0.0004% / top-1 一致 100%** |
| C-9（マスク定数）の適用 | 1件 適用 |
| C-10（Expand→Concat）の適用 | **48件 適用**（24層 × 2） |
| 左右入替（C-8 対策） | **48件 適用** |

**opset を上げても既存の Graph Rewrite はすべて正しくマッチした。**

---

## 2. しかし 24層は壊れている

```
24層 A16W8 素        top-1  1.7%   logits 相対L2 130.6%   fp32top1 の順位 24458位
24層 u16xu8+入替     top-1  4.5%   logits 相対L2 129.0%   fp32top1 の順位 22692位
```

**fp32 との相関は 0.125**（2層は 0.9977）。段階的な劣化ではなく**無相関**である。
**v68 で動かない方式（A16W8 素）でも壊れている**ので、C-8 とは無関係。
**端末以前に、ホスト上の量子化の時点で壊れている。**

6層でも壊れる（top-1 6.2%）。2層は正常（80.7%）。

---

## 3. 原因: 残差ストリームの massive activations

### 残差の大きさが層とともに爆発する

| 層 | 残差の最大 \|x\| |
|---|---:|
| 0 | 6.2 |
| 1 | 7.4 |
| **5〜20** | **約 1677** |
| 23 | 110 |

較正データと評価データの比は 0.97〜1.03 で、**較正のズレではない**。

### 何が起きるか

per-tensor の uint16 量子化はテンソル全体で1つのスケールを使う。
残差のレンジが ±1677 なら **1段階 = 0.051**。

ところが**各層が残差に加える寄与は ±10〜20 程度**である。
つまり「大きな数の上に小さな数を足す」形になり、小さい方が量子化の粗さに埋もれる。

層ごとに fp32 と QDQ の相関を追うと、この構造がそのまま見える:

| テンソル | 最大\|x\| | 相関 |
|---|---:|---:|
| add_30（残差） | 1603.8 | 0.9989 |
| add_35（残差） | 1603.7 | 0.9987 |
| add_42（残差） | 1604.9 | 0.9903 |
| **add_39（層の寄与）** | **20.3** | **0.7224** |
| **add_40（層の寄与）** | **9.3** | **0.6466** |

**残差そのものは保たれている（0.99）のに、層の寄与が崩れている（0.65〜0.72）。**

そして**最後の RMSNorm が大きな成分を正規化で消す**ため、
残るのは崩れた小さい成分——つまりノイズになる。

### 対策を試したが効かなかった

| 試したこと | 結果 |
|---|---|
| **Percentile 較正**（p99.999 で外れ値を切る） | **top-1 6.2% のまま。改善なし** |

外れ値を切っても直らないのは、massive activation が**少数の次元に集中して常時存在する**ためで、
p99.999 でもレンジ内に残る。

---

## 4. これは既知の難問である

LLM の残差ストリームに桁違いの活性化が現れる現象は
**massive activations / outlier features** として知られており、
量子化を難しくする主要因とされている。一般的な対処は:

| 手法 | v68 / QNN で使えるか |
|---|---|
| **per-channel の活性化量子化** | **使えない**（QNN の活性化は per-tensor） |
| **SmoothQuant**（活性化の外れ値を重み側へ移す等価変形） | **使える可能性がある**（オフラインの重み変換なので） |
| 外れ値次元だけ高精度で持つ mixed precision | グラフ分割が必要。QNN 上での実装は重い |
| 16bit より高精度の活性化 | v68 には無い |

**今回は「量子化をどう詰めるか」の話ではなく、手法そのものを変える必要がある。**

### 層分割（チャンク化）では解決しない

「24層を数本の EPContext に分けて fp32 境界で繋ぐ」案は 2GB 問題には有効だが、
**この問題には効かない**。チャンクの入口で残差を受け取った瞬間に同じスケールで
量子化されるためである。2層モデルが正常なのは**層0〜1 の残差が ±7.4 しかない**からで、
チャンク化しても層10〜11 のチャンクには ±1677 が入ってくる。

## 6. 選択肢

| 案 | 内容 | 見込み |
|---|---|---|
| **A. SmoothQuant 相当を入れる** | 活性化の外れ値を重み側へ移す等価変形を前処理に追加 | **本命。ただし実装は小さくない** |
| B. 壊れたまま生成してみる | 24層を端末で動かし、出力を見る | **「動いた」とは言えるが文章にならない見込み** |
| C. より小さいモデルに替える | 残差が爆発しないモデルを選ぶ | 目標（Qwen2.5-0.5B）を変えることになる |
| D. v73 以降の端末 | A16×A16 が使えても **massive activations は別問題**。解決するとは限らない | **この問題には効かない可能性が高い** |

**D は重要な注意点である。** これまで「v73 なら精度が良くなる」と考えてきたが、
**今回の壁は C-8 とは無関係**で、v73 に替えても同じように壊れる可能性がある。
（v73 の利点は `u16×u16` の MatMul と weight sharing であって、
per-tensor 活性化量子化という制約は変わらない。）

## 7. 次

**A（SmoothQuant 相当）を試すのが筋**だと考える。

原理は「`Y = (X/s) · (s·W)` は等価」で、活性化側の外れ値を重み側へ押し付ける。
重みは per-channel 量子化できるので、外れ値を重みに移せば扱える。
本パイプラインには既に**等価変形を挿す枠組み**（`preprocess.py` の各 rewrite）があるので、
そこに乗せられる。

ただし**これは「精度の追い込み」ではなく「手法の追加」**であり、
今回の「動けばよい」というスコープを超える判断が要る。
