# P3: 24層の破綻の真因は RMSNorm だった（C-11）

| 項目 | 内容 |
|---|---|
| 実施日 | 2026-09-13 |
| きっかけ | 「massive activations が真因」という私の推定に対し、**oracle 実験で確かめよ**という指摘 |
| 結果 | **推定は外れ。真因は RMSNorm 内部の `x²`。等価変形で 4.5% → 80.7% に回復** |

---

## 1. 私の推定は外れていた

24層が壊れる原因を「残差ストリームの massive activations が、各層の寄与を量子化の粗さで
潰している」と説明した。**この説明には2つの誤りがあった。**

### 誤り①「層の寄与 ±10〜20 が 1段階 0.051 に埋もれる」

**±10 なら約196段階ある。** 埋もれない。
本当に見るべきだったのは**分布**で、実測するとこうだった:

| 層 | p50 | p90 | max | 1段階 | **p50 が何段階** |
|---|---:|---:|---:|---:|---:|
| 0 | 0.067 | 0.224 | 3.6 | 0.00009 | **755** |
| 1 | 0.106 | 0.337 | 4.8 | 0.00014 | **752** |
| **2** | 0.151 | 0.567 | **749** | 0.0121 | **12.5** |
| 3 | 0.187 | 0.627 | 1604 | 0.0259 | **7.2** |
| 20 | 0.759 | 2.173 | 1634 | 0.0264 | 28.7 |
| 23 | 1.024 | 2.791 | 40.1 | 0.0011 | 906 |

**層2 以降、典型チャンネルは 7〜29段階（実質3〜5ビット）しか使えていない。**
16bit テンソルなのに、である。この観察自体は正しかったが——

### 誤り②「最後の RMSNorm が大きい成分を消すのでノイズが残る」

**RMSNorm は全チャンネルを同じスカラーで割る。** 巨大チャンネルだけを選択的に
消すわけではなく、比率は保たれる。この説明は端的に間違いだった。

---

## 2. oracle 実験で真因を確定させた

「どこの量子化を外すと精度が戻るか」を測った（**診断専用**。量子化を外すと
float が残り C-1 違反になるので本番では使えない）。

6層モデル、ホスト上:

| 除外した箇所 | ノード数 | **top-1** | KL | 相対L2 |
|---|---:|---:|---:|---:|
| なし | 0 | 6.2% | 9.61 | 139.7% |
| **残差（Add）** | 43 | **6.2%** | 9.59 | 139.6% |
| **RMSNorm（Pow/ReduceMean/Sqrt/Reciprocal）** | 52 | **74.4%** | 0.130 | 15.3% |
| 残差 + RMSNorm | 95 | 80.1% | 0.087 | 12.6% |
| 活性化×活性化 MatMul | 12 | 6.2% | — | — |

**残差の量子化を外しても1ポイントも戻らない。RMSNorm を外すと 6.2% → 74.4%。**

→ **真因は RMSNorm の内部であり、残差の量子化ではなかった。**

推定で対策（SmoothQuant）へ進んでいたら、**残差側を直そうとして外していた。**

---

## 3. RMSNorm の何が悪いのか

RMSNorm は `x / sqrt(mean(x²))` である。この **`x²` が量子化される**。

```
通常チャンネル  x ≈ 0.2    →  x² ≈ 0.04
巨大チャンネル  x ≈ 1677   →  x² ≈ 2,812,000
```

per-tensor の uint16 では **1段階 = 2.8M / 65535 ≈ 42.7**。
**通常チャンネルの x²（0.04）は丸ごと 0 に潰れる。**

巨大チャンネルを持つトークンでは `mean(x²)` が巨大値に支配されるので影響は小さいが、
**巨大チャンネルを持たないトークンでは `mean(x²)` が 0 近くに潰れ、
正規化の分母そのものが壊れる。**

---

## 4. 対策: トークンごとの最大値で割ってから二乗する（C-11）

**RMSNorm はスケール不変**である:

```
x / sqrt(mean(x²))  =  (x/m) / sqrt(mean((x/m)²))     （任意の m > 0）
```

そこで **m = トークンごとの max|x|** を使う:

```
変更前:  Pow(x,2) → ReduceMean → Add(eps) → Sqrt → Reciprocal → Mul(x, ·)

変更後:  m  = ReduceMax(Abs(x))          ← トークンごと
         xs = x * (1/m)                   ← xs ∈ [-1, 1]
         Pow(xs,2) → ReduceMean → Add(eps) → Sqrt → Reciprocal → Mul(xs, ·)
```

`xs²` は **[0, 1]** に収まるので 1段階 1.5e-05。**280万倍の改善**である。
さらに `mean(xs²) ≥ 1/C`（最大要素が必ず 1 を取る）なので**分母が 0 に潰れる心配も無い**。

`eps` は元の 1e-6 のままだと m² 倍されて効きすぎるので 1e-12 に置き換えた。
このため**厳密な等価ではない**が、fp32 での差は相対L2 **0.22% / top-1 一致 100%** だった。

実装は `app/pipeline/preprocess.py` の `normalize_rmsnorm_input()`。

## 5. 効果

### 6層

| 方式 | top-1 | KL | fp32top1の順位 | 相対L2 |
|---|---:|---:|---:|---:|
| 従来 | 6.2% | 9.61 | 31219位 | 139.7% |
| **RMSNorm 正規化** | **74.4%** | **0.085** | **1.48位** | **12.5%** |

**oracle 実験で「RMSNorm を量子化しなければ 74.4%」と分かっていた値に、
完全量子化のまま（C-1 を守って）到達した。**

### 24層

| 方式 | top-1 | KL | 相対L2 |
|---|---:|---:|---:|
| 従来 | 4.5% | 10.59 | 129.0% |
| **RMSNorm 正規化 + `u16×u8` + 左右入替** | **80.7%** | 0.548 | 34.9% |

**24層でも 2層と同じ top-1 80.7% に到達した。**（層数を増やしても落ちていない。）

量子化スケールの上位も入れ替わった:

```
変更前: pow_13   range = 2,801,222   1段階 42.74
変更後: add_44   range =     1,778   1段階  0.027   ← pow_* は上位から消えた
```

## 6. 教訓

### 推定で対策を決めない

「massive activations が真因」までは合っていたが、**それがどこで効くか**を外していた。
残差を直そうとしていたら、**まったく効かない対策に工数を使っていた**
（oracle 実験で残差除外は 6.2% のまま＝ゼロ効果と確定した）。

**「原因の説明」と「対策の当たり所」は別物である。**
説明が正しくても、対策の場所が違えば効かない。

### 数字を出す前に分布を見る

「±10〜20 が 0.051 に埋もれる」は、**割り算をすれば 196段階あると分かる**話だった。
最大値だけ見て分布（p50/p90/p99）を見ていなかった。

### oracle 実験は安い

量子化を部分的に外すだけで、5パターン 5分21秒。
**対策の実装より圧倒的に安く、外れを引く確率を大きく下げられる。**
