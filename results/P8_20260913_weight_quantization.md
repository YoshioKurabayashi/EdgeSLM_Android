# P8: 誤差の主因は**重みの量子化**だった — しかも per-channel が効いていない

| | |
|---|---|
| 実施日 | 2026-09-13 |
| 発端 | decode ループの発散原因を探すため、teacher forcing で (ステップ × 層) の誤差を測った |
| 結果 | **活性化ではなく重みが主因**。さらに**重みが per-tensor でしか量子化されていない**と判明 |

---

## 1. 結論

| | |
|---|---|
| 誤差の主因 | **重みの量子化（W8）**。活性化ではない |
| prefill 窓64（実機に載せている） | 全体 18.57% のうち **重み 16.98% / 活性化 7.09%** |
| decode 24層 | 全体 31.19% のうち **重み 29.91% / 活性化 10.85%** |
| なぜそんなに悪いのか | **390本の重みすべてが per-tensor**。per-channel は **0本** |
| 設定は | `get_qnn_qdq_config(..., per_channel=True)` を渡していた。**指定が効いていない** |
| これまでの記録 | 「重みは per-channel」と書いていた（StudyMemo 02 ほか）。**誤り** |

> **このプロジェクトは活性化側ばかり直してきた**（C-8 の MatMul 型、C-11 の RMSNorm、
> 較正データ、キャッシュ I/O）。**測ったら主因は重みだった。**

---

## 2. 分解のしかた

QDQ モデルに対して2つの操作を独立にかけ、4条件で測る。

| 操作 | 内容 |
|---|---|
| **活性化を外す** | 計算ノードの `Q → DQ` を取り除く（`oracle_qdq.py`） |
| **重みを元に戻す** | 量子化済み初期化子 → `DQ` を、**元の float 重み**に差し替える |

### ★ここで一度間違えた

最初は「重みを外す」を **`(q - zp) × scale` を定数に畳む**と実装した。
**これは量子化された値そのもの**で、`DQ` を残すのと数値的に同じである。
道理で「重みを外しても何も変わらない」（31.19% → 31.25%）という結果になった。

**本当に外すには、量子化前の重みを別のモデルから持ってくる必要がある。**

### 妥当性の確認

**両方外したら元の fp32 と一致するはず**である。実測:

| モデル | 両方外したときの相対L2 |
|---|---:|
| decode 24層 | **0.10%** |
| prefill 窓64 | **0.14%** |

残る 0.1% は C-11（RMSNorm 正規化）の ε 近似ぶんで、既知の値と整合する。
**これで分解の道具が正しいと言える。**

---

## 3. 結果

### prefill 窓64（実機に載せているもの、19サンプル）

| 条件 | 相対L2 | top-1 一致 |
|---|---:|---:|
| そのまま（A16W8） | **18.57%** | 73.7% |
| 重みだけ元に戻す（＝活性化量子化のみ） | **7.09%** | 94.7% |
| **活性化だけ外す（＝重み量子化のみ）** | **16.98%** | 68.4% |
| 両方外す | 0.14% | 100.0% |

$\sqrt{16.98^2 + 7.09^2} = 18.4\%$ で合計 18.57% とほぼ一致 ＝ **2つの誤差はほぼ直交**。

### decode 24層（48サンプル）

| 条件 | 相対L2 | top-1 一致 |
|---|---:|---:|
| そのまま（A16W8） | **31.19%** | 68.8% |
| 重みだけ元に戻す | **10.85%** | 87.5% |
| **活性化だけ外す** | **29.91%** | 62.5% |
| 両方外す | 0.10% | 100.0% |

**どちらも重みが支配的。** 活性化を完璧にしても 17〜30% が残る。

---

## 4. ★なぜ重みがそんなに悪いのか — per-channel が効いていない

量子化済み重みの粒度を数えた（prefill 窓64、390本）。

| 型 | 粒度 | 本数 |
|---|---|---:|
| uint16 | **per-tensor** | 222 |
| int8 | **per-tensor** | 168 |
| いずれか | **per-channel** | **0** |

**1本も per-channel になっていない。**

パイプラインは `get_qnn_qdq_config(..., per_channel=True)` を渡している
（`quantize_qdq.py` 64行目）。**指定が反映されていない。**

推測（未確認）: export された重みが `MatMul` の入力に**直接**入っておらず、
`Transpose` を経由した定数（`val_100_quantized` のような名前）になっているため、
ORT の per-channel 量子化の対象から外れている。

### これは本プロジェクトの中心的な話題そのもの

[`DoC/StudyMemo/02_量子化の基礎.md`](../DoC/StudyMemo/02_量子化の基礎.md) 2.4節に
**「per-tensor と per-channel ← 今回の根っこ」**と書いてある。
そこでは「活性化は per-tensor しか使えないが、**重みは per-channel だから扱える**」
と説明していた。**その前提が成り立っていなかった。**

```
896 × 4864 の行列すべてを 1つの scale（256段階）で表している
```

per-channel なら出力チャンネルごとに scale を持てるので、
チャンネル間でレンジが違っても各々に適した目盛りが使える。

## 5. ここまでに踏んだ誤りの型（この調査だけで4つ）

| | |
|---|---|
| **① 1プロンプトで判断した** | キャッシュ統一の「9/24 → 19/24」は偶然。3プロンプトで 28→30（72中） |
| **② 非現実的な分布で試算した** | 一様分布で clip 率 3〜15% と見積もったが実データは **0.0094%** |
| **③ 軌道が違うものを比べた** | 「キャッシュのずれが半減」は分岐して別の文を書いていたから |
| **④ 道具のバグを結果と読んだ** | 「重みを外しても変わらない」は `(q-zp)×scale` を畳んでいたため。**外せていなかった** |

さらに層方向でも1つ:

> **相対L2 の分母が層ごとに違うことを忘れた。** 層プロファイルで「層12・層22 が突出」と
> 読んだが、**絶対誤差 `|ΔK|` は 6.6 → 17.9 と滑らかに増えるだけ**で、
> 凸凹は `|K|` が層ごとに18倍違う（層0と層8の massive activation）ことが作っていた。

**④ を潰せたのは「両方外したら fp32 に一致するはず」という検算があったから**である。
道具に検算を用意していなければ、間違った結論（「量子化では説明できない」）を
そのまま記録していた。

## 6. 次にやること

| # | やること | 見込み |
|---|---|---|
| **1** | **重みを per-channel int8 で量子化できるようにする** | **本命。** 誤差の主因を直接叩く |
| 2 | 1 が ORT の制約で難しければ、QDQ を直接書き換えて per-channel にする | C-8 で同じ手を使った実績がある |
| 3 | v68 が per-channel int8 重みを受けるか実機で確認 | A16W8 の標準形なので通るはず。要確認 |
| 4 | それでも足りなければ重みの丸め方の最適化（AdaRound / GPTQ 相当） | オフライン処理で形式は変わらない |

**v68 では重みを 16bit にはできない**（C-8。`u16 × u16` の MatMul が通らない）ので、
**8bit のまま質を上げる**方向しかない。per-channel はその中で最も効果が大きく、
実行時の形式も変わらない。

## 7. 副産物: decode ループの発散も説明がつく

これまで「decode は単発は良いのにループで分岐する」としていた。
teacher forcing で測ると:

| step | K cache | V cache | logits 相対L2 |
|---:|---:|---:|---:|
| 0 | 10.15% | 22.89% | 27.72% |
| 7 | 10.30% | 23.13% | 28.11% |
| 15 | 10.28% | 23.03% | 31.88% |
| 23 | 10.28% | 23.14% | 19.87% |

**24ステップ回しても誤差は増えていない。** 「累積する」という想定（P6）は外れで、
**最初から 30% 程度の誤差が乗っており、argmax がときどき入れ替わる**というだけである。
その 30% の主因が重みの量子化だった、という話に収束する。
